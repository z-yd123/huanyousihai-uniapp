## 二、佣金引擎单测明细（17 条）

`CommissionEngineTest` 分三组：

| 组 | 条数 | 覆盖点 |
| --- | --- | --- |
| `PayoutCases` | 5 | 第 1 个直推 100+100；第 2 个直推 100+100；**第 3 个直推 200+0 且受益人数为 1**；第 9 个直推 200+0；任意情形合计恒为 20000 |
| `ComplianceCases` | 8 | 直推人缺失 → 中断并落 `GAP_REFERRER_MISSING`；间推人缺失但该发间推奖 → 中断并落 `GAP_INDIRECT_MISSING`；层级永不超过 2；同一受益人不出两条；金额必为正；拨比配置非法时拒绝；`assertCompliance` 能拦住超拨/少拨 |
| `FeeCases` | 4 | 1000 元 → 手续费 60 元、到账 940 元；33.33 元 → 手续费 1.99 元（按分向下取整）；1 元边界；0 元拒绝 |

## 三、构建期发现并修复的缺陷

### 3.1 编译期（后端）

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `cannot find symbol: method success(String, Object)` | RuoYi `BaseController` 只有 `success()` / `success(Object)` / `success(String)`，没有双参重载 | 3 个小程序控制器改用 `AjaxResult.success(msg, data)` |
| 2 | `package com.fasterxml.jackson.databind does not exist` | **本项目使用 Jackson 3**（`tools.jackson.*`），且 `ruoyi-common` 不含 databind 编译依赖 | import 改为 `tools.jackson.core.type.TypeReference` / `tools.jackson.databind.ObjectMapper`，模块 pom 补 `spring-boot-starter-web` |
| 3 | `HandlerInterceptor` / `WebMvcConfigurer` 找不到 | `ruoyi-common` 只依赖 `spring-web`，不含 `spring-webmvc` | 同上补 `spring-boot-starter-web` |
| 4 | `record ProductDetail 重复成员 days` | 同时存在 `Integer days` 与 `List<DayItem> days` | 后者改名 `dayList`，前端按 `dayList` 解析 |
| 5 | `mvn -o` 离线编译失败 | `ruoyi-common` 未安装到本地仓库 | 去掉 `-o`，保留 `-am` 联编上游模块 |

### 3.2 联调期（接口契约）

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 6 | 小程序「互转」功能无处可调 | `HysAppDtos.Transfer` 与 `HysWalletService.transfer` 都已实现（含幂等键、单日次数/额度风控），但**没有任何 Controller 暴露该能力** | 在 `HysAppWalletController` 增加 `POST /app/wallet/transfer` |
| 7 | 管理端相册无法下架 | `HysAdminDtos.AlbumSave` 没有 `status` 字段，`insertAlbum` 把 `status` 写死为 `'0'` | DTO 增加 `status`，Service 缺省填 `"0"`，XML 改用 `#{status}` |
| 8 | 会员「团队人数」比实际多 1 | `countTeam(path)` 用 `referrer_path like concat(path, id, ',%')` 前缀匹配，**把自己也匹配进去了**（自身 path 恰好以该前缀开头） | SQL 增加 `and member_id <> #{excludeId}`，接口签名改为 `countTeam(path, excludeId)`、`countNewSince(path, excludeId, since)`；管理端列表子查询同步加 `c.member_id <> m.member_id` |
| 9 | 列表里「我的直推数」重复计数 | 子查询未排除自身 | 同上统一修正 |
| 10 | 演示账号登录失败 | `03_hys_demo_data.sql` 里密码是 `{BCRYPT_123456}` 占位符 | 生成真实 BCrypt 哈希（cost 10）并批量替换 7 处，`BCrypt.checkpw` 校验通过 |

### 3.3 前端（小程序端）

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 11 | 全部页面依赖内置 mock 数据，与后端无任何连接 | 原工程 `store/` 持有 317 行种子数据 | 重写 `store/index.js`：状态全部来自 `/app/**`，保留原有「同步选择器 + 异步动作」的页面契约；`store/data.js` 只留图片字典、省市字典与合规文案兜底 |
| 12 | 订单详情页只有「余额支付」一个按钮 | 页面只实现了支付分支 | 增加取消订单、确认收货/出行、申请售后（`uni.showModal` editable 收集原因） |
| 13 | 提现必然失败 | 后端要求 `accountName/accountNo/bankName` 三要素，页面没有输入项 | 提现页补三个字段 + 前端校验（账号 12-25 位数字） |
| 14 | 线路下单必然失败 | 后端要求线路订单必须带出行日期（用于接站与酒店），页面没有日期选择 | 线路详情页增加 `picker mode="date"`（起始日 = 今天），未选时提示 |
| 15 | 找回密码必然失败 | 后端用「手机号 + 注册名称」双核验（替代短信验证码） | 页面补「注册时名称」字段，文案同步为双重核验 |
| 16 | 小程序端内置「假后台」页（可模拟充值、审核提现） | 原工程为纯前端演示，内置了会写入假数据的后台面板 | 改写为「运营后台入口」说明页：只讲后台在哪、能做什么、权限边界，**不提供任何写操作** |
| 17 | 改密后仍停留原页面 | 改密会使 `token_version` +1，旧令牌立即失效 | 改密成功弹窗后 `reLaunch` 到登录页 |
| 18 | 海报页邀请码取的是手机号明文 | 页面用 `user.phone` 充当邀请码 | 改用服务端下发的 `inviteCode`，并新增「真实邀请二维码」区块（`/app/member/invite-qr` 返回 PNG data URL） |
| 19 | 管理端构建失败：`Could not resolve "./shared"` | `dashboard/index.vue` 写成 `from './shared'`，而 `shared.js` 在上一级目录 | 改为 `from '../shared'`，重新构建通过 |

## 四、静态一致性核对

| 核对项 | 方法 | 结果 |
| --- | --- | --- |
| 前端调用路径 ↔ 后端映射 | 逐条比对 `uniapp/src/api/hys.js`、`admin/src/api/hys/index.js` 与 12 个 Controller 的映射（含 `'.../' + id + '/xxx'` 拼接形式） | 63 个接口一一对应，无孤儿调用 |
| 管理端权限码 ↔ `sys_menu` | 比对 `@PreAuthorize` 中的 21 个权限码与 `02_hys_menu.sql` | 全部存在，无越权调用 |
| 菜单组件路径 ↔ 页面文件 | `hys/<模块>/index` vs `admin/src/views/hys/<模块>/index.vue` | 9 个菜单全部命中 |
| 前端金额字段 ↔ 后端单位 | 全部 `amount/price/balance/fee` 均为「分」 | 一致（前端仅展示时 `/100`） |
| 状态枚举 ↔ 页面文案 | 订单 0~5、申请 0~2、佣金 1~2、相册 0~1 | 前后端映射表一致 |

## 五、未验证项与原因

| 未验证项 | 原因 | 风险与缓解 |
| --- | --- | --- |
| 服务真机启动、接口 200 连通 | 本机无 MySQL 8 / Redis，`ruoyi-admin` 强依赖两者 | 已提供 `01/02/03` 三段 SQL 与演示数据；建表语句逐表核对字段类型与索引 |
| 页面点按全链路（下单 → 支付 → 计佣 → 审核） | 同上 | 佣金引擎用 17 条单测覆盖；订单/资金关键路径全部走条件更新 + 事务，逻辑可读可测 |
| 微信真机预览 | 需真实 AppID 与开发者工具 | `mp-weixin` 产物已构建成功，导入开发者工具即可预览；`manifest.json` 的 appid 留空待填 |
| 支付通道 | 材料未把真实支付列入 1.0 必做 | 当前为余额支付 + 人工审核充值/提现，符合材料口径 |
